# KVM на Samsung Galaxy A51

[English](README.md) · [Сборка](docs/build.md) · [Архитектура](docs/architecture.md) · [Установка и восстановление](docs/install.md) · [Проверки](docs/validation.md)

**Аппаратная виртуализация заработала на настоящем SM-A515F с Exynos 9611.** Здесь сохранены код, патч ядра, точная конфигурация, инструменты сборки и результаты проверок — чтобы следующий человек мог повторить работу и понять, почему она сработала.

## Проверенный результат

Телефон: **SM-A515F**, Android 11, **A515FXXU5EUJ4**, разблокированный загрузчик. Ядро: **4.14.113-22755563**.

- Android загрузился; обычная перезагрузка также прошла.
- Создан `/dev/kvm`, доступ от root, API версии 12.
- Гостевые инструкции действительно выполняются через `KVM_RUN`: гость записывает число **42** в MMIO.
- Все **8 CPU** прошли проверку; выполнены 12 циклов создания и удаления VM.
- Один и тот же vCPU пережил ожидание и перенос между кластерами в 10 последовательных запусках.
- Виртуальный таймер вызвал настоящий IRQ гостя: **VGICv2, PPI27**, проверено на CPU0 и CPU4.
- После перезагрузки повторно прошли выполнение гостя и оба теста таймера.
- Откат оригинального подписанного UH через Download Mode проверен на телефоне, включая хеш раздела.

Это прототип для **одной проверенной прошивки**. Полноценная гостевая ОС, несколько vCPU, длительная нагрузка, suspend-to-RAM и другие модели пока не проверены. Результаты находятся в [evidence/](evidence/); автоматические тесты QEMU проверяют отдельный синтетический стенд.

## Что пришлось исправить

На A51 уровень EL2 уже занят Samsung UH. Одного `CONFIG_KVM=y` недостаточно. Небольшой шлюз в проверенном NOP-заполнении UH сохраняет исходный контекст EL2 и передаёт управление настоящему коду инициализации Linux KVM. Фиксированный VBAR прошивки остаётся точкой входа исключений; отдельные переходники направляют их в правильные векторы KVM на каждом CPU.

Второй блокер — конфликт IRQ виртуального таймера. Samsung использует архитектурный таймер только как источник счётчика, но всё равно занимал его IRQ. Патч освобождает IRQ в этом режиме: так KVM смог зарегистрировать таймер и создать `/dev/kvm`.

При восстановлении был `SECURE CHECK FAIL (UH)`: Download Mode отклонил полный дамп раздела размером 2 МиБ. Принят оригинальный подписанный контейнер **284 056 байт**, из которого удалено только нулевое заполнение после подписи. Код подготовки такого контейнера сохранён в репозитории.

## Начать без телефона

```sh
sudo apt-get update
sudo apt-get install -y make python3 git binutils-aarch64-linux-gnu gcc-aarch64-linux-gnu qemu-system-arm
git clone https://github.com/SeniorStackOverflow/a51-kvm.git
cd a51-kvm
make check
```

Команда соберёт шлюз и тестовые программы, затем проверит четыре цикла передачи/возврата EL2 в QEMU. Для прошивки нужны собственные резервные копии UH и boot; инструменты отклоняют UH с неподходящим хешем. Сначала прочитай [сборку](docs/build.md) и [восстановление](docs/install.md).

Полные дампы телефона, личный ramdisk, серийный номер и необработанные Android-логи в репозиторий не включены. Код опубликован под **GPL-2.0-only**, исходные уведомления авторов ядра сохранены. Подробности происхождения исходников: [provenance.md](docs/provenance.md).
